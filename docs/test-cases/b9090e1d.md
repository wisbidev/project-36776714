# Test Cases — Static HTML Page (FR-1.x)

## File under test
`index.html` (single file with embedded CSS)

---

## TC-1.1: "Hello Word" heading is displayed and centered
- **Requirement:** FR-1.1
- **Steps:**
  1. Open `index.html` in a browser at viewport width ≥ 768 px.
  2. Observe the page content.
- **Expected result:** The text **"Hello Word"** is visible and centered both horizontally **and** vertically in the viewport.
- **How to verify:** Inspect the layout; the centering technique should use flexbox (`display: flex; justify-content: center; align-items: center;` on the body or a full-viewport container) or CSS Grid.

---

## TC-1.2: Pleasant background colour
- **Requirement:** FR-1.2
- **Steps:**
  1. Open `index.html`.
  2. Note the background colour of the page.
- **Expected result:** The background colour is a soft/neutral tone — e.g. a light pastel, off-white, or a muted colour that is easy on the eyes. Avoid harsh whites or neon colours.
- **How to verify:** Check `background-color` in the embedded CSS within `<style>`.

---

## TC-1.3: Clean readable font
- **Requirement:** FR-1.2
- **Steps:**
  1. Open `index.html`.
  2. Inspect the heading's font-family.
- **Expected result:** The font is a clean, system-UI font stack (e.g. `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`) or an embedded web-safe font. No external CDN font-loading calls — zero external dependencies.
- **How to verify:** Check that `font-family` does not reference an external URL.

---

## TC-1.4: Appropriate heading sizing and spacing
- **Requirement:** FR-1.2
- **Steps:**
  1. Open `index.html` at desktop width (≥ 768 px).
  2. Evaluate the heading size and surrounding whitespace.
- **Expected result:** The heading font size is between **3 rem and 4 rem** on desktop. There is adequate spacing (margin/padding) so the text does not touch the viewport edges.
- **How to verify:** Check the `font-size` and `margin`/`padding` values in CSS.

---

## TC-1.5: Valid HTML5 document
- **Requirement:** FR-1.3
- **Steps:**
  1. Open `index.html` in a source viewer or IDE.
  2. Inspect the document structure.
- **Expected result:** The file starts with `<!DOCTYPE html>`, and contains `<html>`, `<head>`, `<title>`, and `<body>` tags in valid HTML5 form.
- **How to verify:** Run the document through the [W3C HTML Validator](https://validator.w3.org/).

---

## TC-1.6: Zero external dependencies
- **Requirement:** FR-1.3 / Constraint §4
- **Steps:**
  1. Inspect `index.html` source.
  2. Look for any `<link>`, `<script src="...">`, or `@import url(...)` pointing to external domains.
- **Expected result:** No external resources are loaded. All CSS is in a single `<style>` block within `<head>`. No JavaScript is used.
- **How to verify:** Manual source review or a grep for `http://`, `https://`, `@import`.

---

## TC-1.7: Page has a `<title>` tag
- **Requirement:** FR-1.3
- **Steps:**
  1. Open `index.html`.
  2. Look for the `<title>` element inside `<head>`.
- **Expected result:** A `<title>` tag exists and contains a meaningful string (e.g. "Hello Word").
- **How to verify:** Visual inspection of the browser tab label or source review.

---

## Edge: HTML special characters in displayed text
- **Risk:** The heading is "Hello Word" — a simple string, no special characters expected.
- **Expected result:** The literal string "Hello Word" renders correctly, not interpreted as HTML/entities. _Low-risk; verifiable by visual inspection._

---

## Edge: Very long or very narrow viewports
- **Risk:** The heading could overflow or wrap awkwardly.
- **Expected result:** At 320 px width, the text remains fully visible without horizontal scrollbar and without breaking into multiple unintended lines (if it fits). See also FR-2.2.
